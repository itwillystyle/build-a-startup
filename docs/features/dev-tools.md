# Dev tools (SVDev, scenarios, SVCheck, bas, the bot)
**What:** Tools to put the game in a known state and to prove a change. Studio only: the `SVDev` BindableFunction (`DevHook`), `DevScenarios`, `SVCheck`, `StyleBaseline` with `SVStyle`, `tests/smoke_core.luau`, and the chase robot pair `DevRobot` (a scripted player) and `DevRecorder` (a run recorder). Plain Lune from the game folder: `tools/bas.luau` plus the offline tests and sims. The bot is SVDev action `bot`. It plays the real handlers by following the on-screen guide.
**How a player reaches it:** Not a player feature. `SiliconCore` mounts `DevHook` only when `RunService:IsStudio()` (`src/ServerScriptService/SiliconCore.server.lua:4116-4117`), so a published server has no `SVDev`. Reach it in Play, SERVER datamodel: `local p = game.Players:GetPlayers()[1]; local dev = game.ServerScriptService.SiliconCore.SVDev; return dev:Invoke("scenario", p, "list")` (`src/ServerScriptService/DevScenarios.lua:9-12`). `DevRobot` and `DevRecorder` are not mounted by `DevHook`. Each has its own `IsStudio()` guard and does nothing in a live server (`src/StarterPlayer/StarterPlayerScripts/DevRobot.client.lua:19`, `src/ServerScriptService/DevRecorder.server.lua:21`). Lune tools run as `lune run tools/bas help` from the game folder (`tools/bas.luau:1279-1280`).
**Files:**
- `src/ServerScriptService/DevHook.lua`: makes `SVDev` under the SiliconCore script (:44-46). `handle(action, player, arg)` :49, `dev.OnInvoke` :555. 38 actions, one `elseif action ==` each (:53-518): ship, cash, upgrade, wlevel, spinoff, earned, talent, save, bell, rival, launch, buzzoff, wingup, share, peek, wipe, offer, tier, phone, phoneoffer, gopublic, hire, work, product, name, valuation, bot, rolls, item, seats, apt, vip, vippick, recruit, botlog, botstop, scenario, state. Unknown returns "unknown" (:553). No session returns "no session" (:52).
- `src/ServerScriptService/DevScenarios.lua`: `Scen.LIST` :39-43 = snapshot, rich, ready, chase:skilled, chase:star, chase:genius, vip-chase, hq:<n>, home:<0-3>, spinoff, tp:hq, tp:apt, tp:car, tp:candidate:<tier>, tp:vip, tp:door, geo, restock, list. `geo` :184 returns your door (home) and each candidate's `pos` and `pathLen`. `restock` :208 respawns every candidate at a new spot. `tp:door` :281. `chase:<tier>` :219 also returns `pathLen`. `allowed` :45, `snapshot` :58, `restore` :72, `run` :119, `compareSnapshot` :99 (after a restore: does the live save equal the snapshot, ignoring `lastSeen`?).
- `src/StarterPlayer/StarterPlayerScripts/DevRobot.client.lua`: a scripted player for live chase runs. Does nothing until the player has a `RobotProfile` attribute. Profiles `straight`, `dodger`, `spammer`, `idle` (:13-17). Routes with PathfindingService (:38-47), starts the instant `Carrying` is set (:116-122). The run loop is :57-113.
- `src/ServerScriptService/DevRecorder.server.lua`: records one chase run. Start it by setting the `Request` attribute on the DevRecorder script to `"<tier>/<profile>/<anything unique>"` (:6-11, handler :101-104). It restocks, waits 9 s, sets `TestGoal`, `TestFrom` and `RobotProfile`, runs `chase:<tier>` (:45-56), samples every 0.1 s (:65-87) and writes JSON to `ServerStorage.ChaseRun.Value` (:88-97). If the scenario refuses or `geo` has no door it writes `result = "error"` with `err` instead (:57-64). It also makes a BindableEvent `Run` (:27-29), but do not Fire it from the MCP bridge: the handler runs in the bridge's slow thread (:8-10).
- `src/ReplicatedStorage/SVCheck.lua`: `run()` :924 runs five passes: budget :69, screen :125, world :220, placement :373, errors :796. `shot(i)` :847 and `endShots()` :902 take 7 fixed camera framings (`SHOTS` :835).
- `src/ReplicatedStorage/StyleBaseline.lua`: the counts `src/ReplicatedStorage/SVStyle.lua` ratchets against (`run` :287, `baselineSrc` :264). Keys: colours, flatNeutral, neonLoose, offPalette, sharp, untintedPack (parts, untintedOwn are context).
- `tests/smoke_core.luau`: Play, SERVER. Drives SVDev through HQ ups, tier, offer, launch, gopublic, spinoff, save, peek. Returns numbers only, so two runs can be diffed.
- `tools/bas.luau`: `check` :177, `doctor` :182, `sim` :255 (`SIMS` :210), `baseline` :351, `evidence` :374, `scenario list` :474, `map check` :501, `ship` :621 (`onMain` :605: a branch counts as merged by patches, not ids, because GitHub rewrites them), `world` :663, `health` :694, `playtest` :885 (`prep` :852, `robloxLogs` :806).
- `tools/health_lib.luau`: the pure half of the morning run. Studio log parsing (`parseLine`, `saveAndPublish`, `lastRun`), the `[SV]` numbers it reads (`METRICS`), `compareWorld` (a drop in `MUST_NOT_DROP` or a rise in `MUST_NOT_RISE` fails; other moves over 10% are reported; new kinds of warning are reported), and the ship rules (`SHIP_LIVE_DAYS` 2, `SHIP_BRANCH_DAYS` 7). Tested in `tests/offline/health.spec.luau` against planted logs.
- The morning run: `lune run tools/bas health` writes `../HEALTH.md` (in `silicon-startup/`, outside the repo). It runs lint, tests + sims + drift, the map, `ship` and `world`. It never commits, pushes or publishes. State in `.bas/`: `world.json` (the last good Play run; a clean run replaces it) and `health.json` (the last run, for "changed since").
- The game doctor (11 Oct): `src/ServerScriptService/GameDoctor.server.lua` plays the game in Studio Play as Wilz and each step checks itself against a number it expects (`run` :168): world (sinking, meshes through floors, lift stops over nothing, drop-off routes, scripts that exist twice), `hq:5/9/13/18` (drop-off on the ground, cards over cards, buttons covered, stand on every storey, the lift to every stop, the camera behind walls), `chase:skilled/star/genius` with DevRobot (outcome, camera cuts a second, the lens behind walls, the hunter's run animation, hitches) and script errors. It refuses to run without a save snapshot; the save is restored after Play stops. Trigger: `GameDoctor:SetAttribute("Request", "full/" .. os.clock())`, poll its `Status` attribute until "done", read `ServerStorage.DoctorReport` (JSON). What only the player's screen can see is measured by `src/StarterPlayer/StarterPlayerScripts/DoctorClient.client.lua` running `src/ReplicatedStorage/DoctorProbes.lua` (`ui` :59, `camera` :173, `chasecam` :200; the per-frame rules `isCut` :32 and `isStutter` :37) when the server sets the `DoctorProbe` attribute; it answers on `ReplicatedStorage.DoctorResult`. `lune run tools/bas checkup report <json>` (`cmdCheckup` `tools/bas.luau:1066`) judges it with `tools/doctor_lib.luau` (`findings` :27, `diff` :60 by family, so one problem on four HQ levels is one finding; `markdown` :99, `discord` :142) into `../DOCTOR.md` and `../DOCTOR-discord.txt`; `bas checkup post` sends the summary to the Discord webhook in `../.discord-webhook` (Discord URLs only). The scheduled routine is the `game-doctor` skill; `tools/routine.sh` is the one fixed script every routine calls. Its first runs found the drop-off on the entrance arch, the chase camera inside the HQ, and every new file doubled by two Rojo plugins. Tested in `tests/offline/doctor.spec.luau`.
- The doctor as a PR gate (12 Oct): `lune run tools/bas checkup pr <report> <fingerprint> [--post]` (`cmdCheckupPr` `tools/bas.luau:998`) passes a PR only if the src tree is clean, every src file's hash matches a script Studio ran (`src/ReplicatedStorage/SourceHash.lua`: `hash` :18, FNV-1a with CR removed; `collect` :36, run in Studio's Edit datamodel; `nameOf` :53; `compare` :65), the fingerprint and report are newer than the commit, and `doctor_lib.prVerdict` (`tools/doctor_lib.luau:173`) finds no BLOCKER and no BUG that main's last posted run lacked. `--post` comments on the PR and sets the `doctor` commit status. Steps: the `game-doctor` skill, PR mode. Tested in `tests/offline/sourcehash.spec.luau`. First use: it failed PR #48 on a non-solid meeting table every other check had passed.
- The playtest review (10 Oct): `lune run tools/bas playtest list | prep <video>|--new | done <video>` turns a screen recording into `../playtests/<name>/` (outside the repo): contact sheets with the time burned in, what he said (`tools/playtest_speech.py`, faster-whisper small.en) and what the game printed on the video's clock. A recording counts as a playtest when a Roblox log shows this game running while it was filmed (`tools/playtest_lib.luau`: `sessions` :62 reads Studio Play and the Roblox app's `Joining game ... place` line, `PLACES` :55; `window` :109). The review itself, a guard per finding and the check against main, is the `playtest-review` skill. Tested in `tests/offline/playtest.spec.luau`.

**Prove it:**
- `bas check` = selene on `src tests tools` plus `lune run tests/offline/run` (219 pass, 13 spec files at a96f2d8) (`tools/bas.luau:177-180`).
- `bas baseline diff` compares tests passed, chase escape rates (default tolerance 5 points), spin price, wait and night cover, and `maxPrestigeSec`. Rows, play styles or spins in the baseline that the new run no longer reports are flagged too (`diffBaseline` `tools/bas.luau:288-349`).
- `bas map check` checks every `src` module is named on a page here, and that no cited file changed after the page's commit (`tools/bas.luau:501-564`).
- `SVCheck` cannot see server errors, a second player, or whether the game is fun (`SVCheck.lua:24-28`). Nothing tests `DevHook` or `DevScenarios` themselves.
**Gotchas:**
- Use `SVDev`, not `require`. A `require` from execute_luau returns a fresh module copy, so it drives an unused copy of the game (`DevHook.lua:103-106`, `DevScenarios.lua:14-15`).
- `scenario` is limited to Wilz and negative ids (`DevScenarios.lua:45-47`). The raw actions `wipe`, `cash`, `spinoff` and `save` check nothing.
- `scenario spinoff` needs a snapshot taken in this server (:256) and always returns ok = true (:262). It is the only scenario with that gate: `rich`, `ready`, `chase`, `hq`, `home` and the rest change the test save without one (header :22-26).
- `hire` only adds the first intern while TalentDrop is on (`SiliconCore.server.lua:1934`). Use `recruit`.
- The bot stops after `runs` spin-offs or 45 minutes per company (`DevHook.lua:434,465`). It stops if the session is replaced (:208).
- `StyleBaseline.lua:6` says SVStyle "fails on any rise". `SVStyle.run` only returns a text VERDICT line (`SVStyle.lua:341-348`). It is not part of `SVCheck.run` or `bas`.
- `SVCheck` budget numbers are fake when the Studio window is not rendering. It says so when all four views match (`SVCheck.lua:103-111`).
- `smoke_core` mutates the save (apt, HQ, spin-off). Snapshot first (`smoke_core.luau:6-7`).
- DevRecorder runs in the first player's server and needs `SVDev` (:34-36, :41-44). It sleeps 9 s after the restock because each chase candidate tries up to 12 pathfinding routes (`TalentDrop.lua:168-186`). It grades `result` by staff count: `home` if staff rose, else `timeout` if the player got within 20 studs of the door, else `caught` (:90). So a catch inside 20 studs of the door reads as `timeout`.
- Studio frame rate decides whether a robot run means anything. On 9 Oct Studio ran at 2.6-6 FPS (Edit mode 169 ms/frame), so live dodge and BOOST results are not valid yet. Code pasted through the MCP bridge is resumed only about every 0.39 s, which is why DevRobot is a real LocalScript (`DevRobot.client.lua:1-6`).
- `bas scenario list` reads `Scen.LIST` with the pattern `Scen%.LIST = (%b{})` (`tools/bas.luau:476`). Keep it a plain list of strings.
- `bas` must run from the game folder, where `default.project.json` is (`tools/bas.luau:1279-1280`).
- `bas risk` (13 Oct): `lune run tools/bas risk [base] [--label]` (`cmdRisk` `tools/bas.luau:1166`) lists every file the branch changes (vs `origin/main`, plus uncommitted and untracked), the kind of change each is, and whether Luke must look before a merge. The rules are pure, in `tools/risk_lib.luau` (`RULES` :40, `kindOf` :64, `classify` :75): judge (tests, the seeded sims, the doctor, SVCheck, SourceHash, the UI audits, CONSTRAINTS.md, STYLE-SPEC), ci (incl. `Packages/`, which ships to players), save, economy, gameplay and **unknown** (a path no rule knows) need Luke; tooling and docs are routine. Renames list both paths (`--no-renames`), so a test moved out of `tests/` cannot pass as routine. `--label` tags the open PR `needs-luke`. Tested in `tests/offline/risk.spec.luau`. From the Anthropic source-control article: approval rules by meaning, humans review intent.
- `CONSTRAINTS.md` (13 Oct, repo root): the 16 rules that have each cost a session. Every reviewer checks a change against it first; a broken rule is Critical.
- The save fuzz (13 Oct): `tests/offline/savefuzz.spec.luau` throws 4,000 seeded random saves (NaN, infinities, strings, nested tables, nil) at every pure function SaveLoad passes raw data through (`StaffStats.clampLevel`, `validPin`, `fixIds`, `Momentum.sanitize`, `Journey.cleanFlags`, `cleanTips`) and checks rules that must hold for any input; a failure prints the seed and the input. Planted on 13 Oct, it caught a missing NaN guard, duplicate staff ids and a junk journey flag. Since the #52 review it also checks that a valid saved id is kept (a `fixIds` that renumbered everyone passed the other rules) and feeds real tip ids to `cleanTips`. It does not reach SaveLoad's own `clampInt` or the world-building half of `applySave` (not pure).
- Manage Staff phase 2 (14 Oct): DevHook `staffact` (`DevHook.lua:540`, `"train:i:stat"` or `"move:i:dept"`, i = list position) runs the REAL `Econ.staffAction` and returns ok/why/price/cashSpent and the person; the doctor's `team` step (`GameDoctor.server.lua:340`) uses it. `tools/fuzz_remotes.luau` ends with a StaffAction round of real-shaped actions (report `staffAction`: fired, replies, accepted, cash before/after).
- The exploit check: `tools/fuzz_watch_server.luau` (server datamodel, first) and `tools/fuzz_remotes.luau` (client, `FROM, TO` = 1, 17 then 18, 99). Procedure and the legit flags to expect: `.claude/skills/verify-game/SKILL.md`, "Exploit check". The save snapshot does not cover `SVNames_v1`: check it after.
- The cloud smoke (every PR, `.github/workflows/cloud-smoke.yml`): `tools/smoke_project.luau` builds the project plus `ServerStorage.SmokeBoot`, a ModuleScript copy of `SiliconCore.server.lua` (a Luau Execution task does not run Scripts: the DataModel is not running). `tools/cloud_smoke.luau` uploads it to the TEST experience (universe 10770080927, place 104511165501086, owned by the Wilz alt) as a SAVED version, never published, and runs `tools/smoke_task.luau` there: boot to the banner, require every ModuleScript, fail on any error. After the boot it also runs the two 10 Oct loops: `WorldHealth.sinking` (a surface you would sink into) and `TalentDrop.health` (a drop-off with no route, a chase tier with no spot); see world-build.md and chase.md.
